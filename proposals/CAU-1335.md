# CAU-1335 — Reproduce and fix proposal writes landing in the wrong repo folder

**Archetype:** bugfix
**Status:** APPROVED 2026-08-25 — implemented; verification results recorded below

## Story anchor

- A first-time adopter's `/process-transcript` run wrote proposal files under a different repo's folder instead of the expected project (adopter feedback round 2026-08-19, ported from awowio/AWO-214).
- Acceptance criteria: (1) the report is reproduced or ruled out; (2) root cause identified against the `{HUB}`/`{PROJECT}` resolution path, fix or explicit guard landed; (3) a wrong-root write fails loud rather than silently landing elsewhere.
- Out of scope: redesigning the resolution ladder itself; restoring the payload's setup bootstrap tooling (adjacent finding, follow-up below).

## Root cause

**The repo-boundary rules exist, but no adopter session can read them.** The §Context resolution ladder (AWO-61, landed 2026-08-18 in `.agents/AGENTS.md`) is the only text that defines installation resolution and forbids crossing a repo boundary — and it does not ship in any plugin payload. `dist/` carries only dangling pointers to it: `using-awow` ("Resolve per §Context resolution in AGENTS.md — never guess across a repo boundary") and `workitem-write` ("Resolve per §Context resolution in the agent instructions"). A first-time adopter has no `AGENTS.md` of any kind, and `{AWOW_ROOT}` ships no copy, so the pointer resolves to nothing.

The session reflex is the sole resolution guidance a plugin session gets, and for `{PROJECT}` it says only "resolve[s] to the repo root here." In an ambiguous workspace — CWD above sibling repos, or an unscaffolded repo beside a scaffolded one — nothing in context tells the agent what "here" is or that a sibling repo is off-limits, so content cues (a transcript discussing another repo's work) can pull `{PROJECT}/proposals/` writes across the repo boundary. And because enforcement is prompt-only, a wrong-root write succeeds **silently** — there is no mechanical check anywhere in the write path.

Timeline corroboration: the ladder landed one day before the feedback round, in a file no adopter receives; the incident and the gap are consistent for every payload version, including current `dist/` (0.12.0).

**Exact incident replay is impossible:** the original awowio/AWO-214 is unreachable from this workspace and no local record of the feedback round exists. AC1 is therefore satisfied mechanistically — reconstruct the reported conditions and demonstrate the failure against the shipped payload.

## Validation (2026-08-25) — mechanism reproduced

Headless `claude -p --plugin-dir dist` (payload 0.12.0, user-scope plugins disabled, `--strict-mcp-config`) against a scratch workspace: `notes-app/` (fresh, unscaffolded, holds a transcript discussing the sibling's work) beside `tables-service/` (scaffolded, file-based fixture board).

- **CWD inside the fresh repo: correct conduct, twice.** `/process-transcript <file> --yes` stopped loud at Gate 2 — "no board wiring at all" — offered `/setup-awow`, wrote zero files.
- **CWD at the workspace root: reproduced.** The same invocation discovered the sibling, announced `targeting board: tables-service`, and after a single `go` executed cross-boundary: edited `tables-service/context/tooling/board.md`, created `tables-service/context/knowledge-base/decisions/v2-cutover-copy-on-write.md`, and wrote `.awow/board-session.md` + `.awow/no-setup-prompt` at the bare workspace root. `{PROJECT}` fragmented three ways in one session (board+KB → sibling, session state → non-repo workspace root). Nothing failed loud; the only flag was one prose sentence inside the Gate-2 message — model prudence, not a shipped rule.

Evidence: run logs at the session scratchpad (`repro-run1.jsonl`, `repro-run2.jsonl`, `repro-run2b.jsonl`); not committed (session-derived).

## Plan

1. **Reproduce (AC1)** — new eval suite `tests/wrong-root-writes/` (the existing `tests/context-resolution` suite is pinned to the read-only `/my-work`; this bug needs a *writing* flow):
   - Fixture: a workspace root over two sibling repos — `repo-sibling/` (a scaffolded installation, standing in for the repo named in the incident; keep the adopter's real repo name out of this public repo) and `repo-fresh/` (unscaffolded, the session's CWD). Setup hook `git init`s both, per suite conventions.
   - Script: hand `/process-transcript` a transcript whose content discusses `repo-sibling` work; scripted `go` replies drive it toward drafting.
   - Checks: `post()` asserts **no file exists** under `repo-sibling/` beyond the fixture (`file-absent repo-sibling/proposals`) — the deterministic regression assert. Rubric grades conduct: the unscaffolded outcome (offer `/setup-awow`, or a loud stop) and never a borrowed installation.
   - Run against the pre-fix payload: an over-the-boundary write or borrowed installation reproduces the report; a clean loud stop rules it out for the current payload (the fix below still lands — the shipped channel provably lacks the guard text either way).
2. **Fix (AC2)** — ship the rules to the channel that was missing them:
   - `.agents/context/` gains the ladder as payload machinery (e.g. `context/context-resolution.md`), gathered into `dist/` so `{HUB}`-first/`{AWOW_ROOT}`-fallback resolves it for every adopter — the same read rule all other machinery follows.
   - Repoint the dangling references in `using-awow` and `workitem-write` from "AGENTS.md" to that machinery path. `.agents/AGENTS.md` §Context resolution becomes a pointer to (or verbatim include of) the same file so the two cannot drift.
   - The `using-awow` reflex additionally carries the compact invariant inline — it is the only text guaranteed to be in context: never resolve `{PROJECT}` across a repo boundary; an unscaffolded repo means offer `/setup-awow`, never a borrowed sibling; ambiguity means ask, and announce the resolved installation before the first write.
3. **Guard (AC3)** — wrong-root writes fail loud:
   - Claude channel, mechanical: extend `hooks/hooks.json` with a `PreToolUse` hook on `Write|Edit` (new `hooks/wrong-root-guard.py`, same shim pattern as `lifecycle-seam-check`). **Git-boundary-aware, not project-dir-aware** — the reproduction showed `CLAUDE_PROJECT_DIR` is the workspace root when CWD sits above the repos, so a project-dir check passes exactly the writes that must be caught. Rule: for a write targeting an awow artefact path (`*/proposals/*`, `*/context/knowledge-base/*`, `*/context/team/*`, `*/.awow/*`), resolve the target's enclosing git root; allow when it equals CWD's enclosing git root or the mapped hub (`$AWOW_HUB` / `.awow/hub.json`); otherwise return permission decision **ask** naming the crossing (which denies loudly in a headless run). Scoped to awow artefact paths deliberately — scratch and unrelated writes stay untouched.
   - All channels, prompt: the reflex invariant from step 2 is the guard text for harnesses without a hook surface.
4. **Board** — move CAU-1335 to In Progress on approval; comment with the root cause; PR links the item.

## Risks

- **Reflex growth** — the session-start injection is read every session; the inline invariant must stay to a few lines, with the full ladder behind the machinery path. Mitigation: word-budget the diff in review.
- **Guard false positives** — spoke sessions legitimately write outside the project dir (to the mapped hub); the maintainer repo writes fixtures containing `proposals/` paths (inside the project dir, so allowed). Mitigation: allowed-roots design above plus hook unit tests for both cases.
- **Adjacent finding, not acted on:** the payload ships neither `tools/bootstrap-claude-md.py` nor the `AGENTS.md` stub, so `/setup-awow` Step 5 cannot run as written on the plugin channel — a completed setup still leaves the adopter without the ladder. Follow-up proposal stub: `proposals/payload-bootstrap-gap.md`.
- **Adjacent finding, not acted on:** ladder Stage-1 rule 4 auto-adopts a lone child installation from a workspace root with only a one-line announcement — acceptable for reads, arguably too quiet for file writes. Record for the team; do not widen this fix.
- **Adjacent finding, not acted on:** in both headless runs the session reported the payload's lens registry (`dist/handlers/_meeting-archetypes/`) as "outside this session's allowed directories" — plugin-root reads can be permission-blocked in `-p` mode, so shipped machinery silently degrades to ad-hoc extraction. Separate story.
