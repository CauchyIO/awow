# CAU-1338 — Warn when a vendored install's machinery drifts behind the installed plugin payload

**Archetype:** bugfix
**Status:** DRAFT 2026-08-25 — awaiting approval
**Design spec:** [vendored-drift-warning-design.md](vendored-drift-warning-design.md) (normative: stamp format, detection table, verbatim messages and doc edits, test matrix, open-PR review). Implementation plan: [plans/2026-08-25-vendored-drift-warning.md](plans/2026-08-25-vendored-drift-warning.md).

## Story anchor

- Observed 2026-08-19 (ported from awowio/AWO-217): a session on a branch cut before PR #62 (e3ec3c8) rendered the old plain-text board-plan gate while the installed 0.9.2 payload — built from the #62 merge commit — already carried the diff-style grammar. The user expected the new output and had no way to see why it was missing.
- Acceptance criteria: (1) a session detects vendored machinery older than the installed plugin payload and surfaces a one-line drift warning; (2) the precedence rule (vendored beats payload) and its branch-vintage consequence are documented where adopters will find them; (3) the payload version string distinguishes rebuilds.
- Scope note: CAU-1340 (Done, PR #64) retired the vendoring route and explicitly left "the maintainer-branch drift case" to this item. The remaining vendored population is this maintainer repo plus legacy adopters pending `/migrate-to-plugin` — the fix must serve both, and creates no new vendored installs to serve.

## Root cause

**Design cause — the precedence is intent-blind.** The `{HUB}`-first machinery rule (`.agents/AGENTS.md` §Reading machinery; `context/tooling/context-resolution.md`) exists so a contract a team vendored *and deliberately edited* beats the shipped default. But the rule keys on file presence alone: a vendored file that is merely *old* — a branch cut before an upstream change, an install never updated — wins identically. Deliberate customization and accidental staleness are indistinguishable, and both win silently.

**Enabling cause — no check at the one place that could make one.** `hooks/session-start.py` tiers every session (vendored install / spoke / plain repo) and already does exactly this kind of drift detection for spokes — `SPOKE_DRIFTED` verifies the recorded hub link against the clone's actual origin. The vendored tier has no equivalent, even though `build_context()` holds both roots in hand: `plugin_root` (the installed payload) and `repo_dir` (the vendored tree).

**Blocking cause — no comparable vintage marker exists even if the hook checked.** Every payload manifest's `version` is copied verbatim from `.claude-plugin/plugin.json` (`tools/gather.py`); rebuilds from different commits carry the same string, so "0.9.2" names a version, not a content vintage. This blindness has already bitten once at the mirror level: AWO-156 (documented in `tools/check-dist-published.py`) — installs resolved two minors behind while CI stayed green. The vendored side is no better: `tools/awow.lock.json` records only the t0 install `awow_version`, and this repo's own copy is itself stale (0.7.0, listing files PR #66 deleted).

Today's maintainer topology makes the drift bidirectional: since AWO-257 (PR #66) commands and skills load from the installed marketplace snapshot of `dist/`, while `{HUB}`-first machinery reads follow the branch's working tree — one session mixes two vintages whenever branch ≠ snapshot, in either direction, with no signal either way.

Exact incident replay is unnecessary: the mechanism is structural, fully present in the current tree, and the issue records the observed instance.

## Plan

1. **Build stamp (AC3)** — `gather.py` digests each payload's planned stubs (sha256 over sorted `(relative path, content)` pairs, the stamp file excluded from its own input) and writes `<payload>/.claude-plugin/build.json`: `{"version": "<semver>", "content": "sha256:<12 hex>"}` for `dist/` and `dist-telemetry/`. Content-derived only — no clock, no commit hash — so the build stays a deterministic function of the source tree and `--check`/CI stay green. Display form where a version is printed: `0.12.0+<digest>`. The `awow-dist` mirror inherits the stamp through `sync-dist.sh` unchanged.
2. **Session-start drift check (AC1)** — a vendored-tier check in `hooks/session-start.py`, mirroring the spoke tier's shape:
   - **Maintainer checkout** (`repo_dir` carries `dist/.claude-plugin/build.json`): compare the branch's `dist/` stamp against the installed `plugin_root` stamp. Differ → one line naming both (version + digest each), stating that machinery reads follow the branch (`{HUB}`-first), with the remedies: `python tools/gather.py && claude --plugin-dir dist`, or re-sync the plugin. Deliberately fires in both directions — the inverse (stale plugin cache behind the branch) is AWO-156 at the cache level and equally silent today.
   - **Legacy vendored adopter** (`tools/awow.lock.json` with `awow_version`, no dist stamp): compare the lock's version against the installed payload's. Older → one line naming both vintages, that vendored files win, and `/migrate-to-plugin` as the exit.
   - Detection order: maintainer branch first — this repo's stale lockfile must not route it into the adopter branch.
   - One line, every affected session, no opt-out file: it reports a live condition, same policy as `SPOKE_DRIFTED`.
3. **Document the precedence and its consequence (AC2)** — `context/tooling/context-resolution.md` gains a short **§Machinery precedence and vintage**: vendored-beats-payload exists for deliberate edits; its consequence is that a vendored install's machinery vintage is the current branch's, not the installed plugin's; the session-start warning names drift and `/migrate-to-plugin` retires it for adopters. `.agents/AGENTS.md` §Reading machinery gets one consequence sentence pointing there (pointer, not copy — the CAU-1335 no-drift pattern). Harnesses without a SessionStart surface get AC2 as their guard — the same hook-where-available / prompt-elsewhere split CAU-1335 shipped.
4. **Board** — on approval: move CAU-1338 to In Progress, comment the root cause, PR links the item.

## Risks

- **Digest orders nothing.** When versions are equal but content differs, the warning can say "differs", not "older". Accepted: the AC's substance is a surfaced one-line signal where today there is none; semver still orders the cross-version cases (the recorded incident included).
- **Stamp self-reference.** `build.json` must be excluded from its own digest input (compute over the plan, then append the stamp stub) or the build never converges.
- **Reflex growth.** The session-start injection is read every session; the warning stays one line and only renders in a drifted vendored install.
- **Adjacent finding, not acted on:** this repo's `tools/awow.lock.json` is stale (0.7.0, lists files deleted by PR #66) — flag for cleanup; the detection-order rule above already defuses it here.
- **Adjacent finding, not acted on:** `tools/check-dist-published.py` compares bare versions and could adopt digest comparison for a sharper AWO-156 guard — follow-up, out of scope.

## Verification plan

- **Stamp determinism:** two consecutive `gather.py` runs byte-identical (`--check` green both times); editing any planned source file flips the digest.
- **Hook unit tests** (`tests/hooks/test_session_start.py`, wording asserted per house convention): maintainer drift in both directions, matching stamps → silent, adopter vintage warning, stale-lockfile-beside-dist does not misroute, absent stamp (pre-fix payload) degrades silent.
- **Incident-shape regression:** a fixture pairing an older repo `dist/` stamp with a newer installed-payload stamp — the 2026-08-19 shape — must emit the warning line.
- **Full local CI battery green** (gather `--check`, tokens, manifests, hooks suites, harness checks).
